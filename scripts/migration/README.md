# Kobo → Supabase test-data migration

Migrates the existing Kobo dataset (`Data Migration Remaining.xlsx`) into the
live Supabase project so the web dashboard flow can be tested end to end.

**Safety rules for this task**

- Nothing in this folder deletes anything. No script issues `DELETE` against
  Supabase or Kobo.
- The Kobo submissions are the only copy of the source data. Scripts only
  ever `GET` from Kobo.
- All inserts are idempotent (keyed on the sheet's `Unique code` / Kobo
  `_uuid`), so a re-run updates rather than duplicates.

## Layout

```
scripts/migration/
  00-inspect-db.mjs     read-only schema + reference-data dump   ← run this first
  data/
    production_entries.json   93 pyrolysis entries, normalized
    mixing_entries.json       16 mixing entries, normalized
    issues.json               81 rows flagged by the earlier import attempt
    summary.json              counts / distinct values
    db-snapshot.json          (generated by 00-inspect-db.mjs)
```

The three normalized JSON files are already generated from the spreadsheet —
no Excel parsing needed at migration time.

## Step 0 — inspect the DB (read-only)

```bash
cd <repo root>
node scripts/migration/00-inspect-db.mjs
```

Reads `Backend/.env`. Writes `scripts/migration/data/db-snapshot.json`.

This is needed because the base schema for `kontikkis`, `biochar_producers`,
`producer_sites`, `farms`, `users` and `feedstocks` is **not** in
`Backend/supabase/migrations/` (those start at `004_`) — it only exists in the
live database. Without the snapshot the migration would be guessing at NOT NULL
columns and check constraints.

`db-snapshot.json` contains real operator names and emails — it is gitignored,
keep it local.
